# 오늘의 패치

게임을 검색해 선택한 뒤 아이온2 공식 공지, 업데이트, CM 아지트와 패치 후 추천 할 일을 확인할 수 있는 웹 UI입니다. Figma의 화면 구조와 Notion 서비스 기획의 1차 출시 범위를 참고했습니다.

## 로컬에서 실행하기

### Node.js 없이 바로 열기

파일 탐색기에서 `index.html`을 더블클릭하세요. 정적 화면과 검색·필터 기능을 바로 사용할 수 있습니다. CSS와 JavaScript 경로를 상대 경로로 지정해 `file://`에서도 열리도록 구성했습니다.

### 로컬 서버로 실행하기 (선택)

Node.js 18 이상이 설치되어 있으면 추가 패키지 설치 없이 실행할 수 있습니다.

```bash
node server.js
```

터미널 창을 켜둔 채 브라우저에서 [http://localhost:4173](http://localhost:4173)을 여세요. 다른 포트를 사용하려면 Windows PowerShell에서 `$env:PORT=5000; node server.js`로 실행합니다.

### 아이온2 공식 게시판 크롤링 및 AI 요약

크롤러는 아이온2 공식 공지, 업데이트, CM 아지트 게시판의 게시물을 가져온 뒤 Google AI Studio에서 발급한 키로 Gemini API를 직접 호출해 요약·분석합니다. CM 아지트는 아이온2 전용 게시판입니다. API 키를 프로젝트 파일이나 채팅에 쓰지 말고 Windows 사용자 환경 변수로 설정하세요.

1. [Google AI Studio API 키 페이지](https://aistudio.google.com/apikey)에서 API 키를 만듭니다.
2. Windows 검색에서 `계정의 환경 변수 편집`을 열고 사용자 변수의 `새로 만들기`를 누릅니다.
3. 변수 이름에 `GEMINI_API_KEY`, 변수 값에 Google AI Studio에서 발급받은 키를 입력하고 저장합니다.
4. 열려 있는 PowerShell을 닫고 새로 연 뒤 프로젝트 폴더에서 크롤링을 실행합니다.

```powershell
cd C:\Users\user\Desktop\Todaypatch
npm run crawl
```

크롤러는 `gemma-4-31b-it` 모델을 Google Gemini API의 `generateContent` 주소로 직접 호출하고, JSON 형식의 요약·분석 결과를 검증한 다음 `data/aion2.js`에 저장합니다. 원문은 24,000자에서 잘라내지 않고 전체를 전달하며, 각 공지를 개별 요청으로 분석해 한 번의 출력 토큰 예산을 여러 글이 나눠 쓰지 않도록 했습니다. AI에는 일반 공지 5~8문장, 긴 업데이트 8~14문장과 주제별 파트, 날짜·수치·대상·예외·제한을 구체적으로 남기도록 요청합니다. 이 설정은 크롤링 시간이 더 오래 걸리고 무료 모델의 일시 오류나 사용량 제한을 만날 가능성도 커집니다. Google API가 429 또는 5xx 오류를 반환하면 같은 모델로 최대 세 번 대기 후 재시도하며, 실패할 경우 기존 데이터는 유지됩니다.

현재 PowerShell 창에서만 키를 설정하려면 아래처럼 실행할 수도 있습니다. 따옴표 안의 예시를 실제 키로 바꾸세요. 이 방식은 새 터미널을 열면 사라집니다.

```powershell
$env:GEMINI_API_KEY = "YOUR_GOOGLE_AI_STUDIO_API_KEY"
npm run crawl
```

크롤링 기본 기준일은 한국 시간 2026년 11월 18일이며, 세 공식 게시판에서 그 날짜 이후 게시물을 가져옵니다. 기준일은 `$env:AION2_CRAWL_SINCE = "YYYY-MM-DD"`로 바꿀 수 있습니다.

- [공지](https://aion2.plaync.com/ko-kr/board/notice/list)
- [업데이트](https://aion2.plaync.com/ko-kr/board/update/list)
- [CM 아지트](https://aion2.plaync.com/ko-kr/board/cm_story/list)

상세 화면과 검색은 미리 크롤링해 저장한 AI 요약·분석을 사용하고, 공식 본문은 출처 링크로 연결합니다. 원문 본문 자체는 사이트 데이터에 저장하지 않습니다. Vercel 배포 중에 크롤링이나 AI 분석이 자동 실행되지는 않습니다. 요약 품질 개선을 적용하려면 키가 설정된 PC에서 `npm run crawl`을 실행해 `data/aion2.js`를 새로 만든 뒤 그 데이터 변경을 함께 push해 재배포해야 합니다. API 키 누락, 크롤링 실패, 요약 오류가 발생하면 기존 데이터는 유지됩니다.

## 화면과 동작

- 메인 화면: 게임 검색과 팔로우 게임 아이콘 목록(한 줄 최대 4개, 보유 개수에 따라 자동 확장), 게임 둘러보기의 ‘다른 게임’·‘곧 출시하는 게임’ 탭
- 게임별 커뮤니티: 전체 게임 공통으로 최신순·인기순, 게임·글 종류 필터와 키워드 검색 제공. 글 종류는 자유게시판·질문·공략·토론으로 제한
- 이메일 계정: 이메일·비밀번호로 가입·로그인해 게시글·댓글·좋아요·신고 사용. 비밀번호는 scrypt 해시로 저장하고, 세션은 HttpOnly 쿠키로 유지
- 공개 게시글은 작성자가 ‘게시하기’를 누를 때 서버에 저장. 작성자만 수정·삭제하며, 개인 메모는 기존처럼 `localStorage`에 별도로 저장
- 게시글은 게임, 글 종류, 제목, 본문, 태그, 작성자, 작성일을 저장. 공식 공지에서 시작한 글은 원문 URL과 선택한 요약·분석 항목을 함께 연결
- 공지 상세의 ‘이 공지로 질문하기’·‘토론 시작하기’는 연결 정보가 채워진 글쓰기 화면을 엽니다. 공지에서 추출한 기간·보상·직업·스킬 등 태그 후보를 작성자가 선택
- 댓글·좋아요 알림은 계정 알림 목록에 저장. 로그인 시도 제한, 신고 접수, 글 작성 반복 제한, 운영자 검토 화면과 게시글 숨김 제공
- 이미지 첨부와 실시간 채팅은 첫 버전에서 제공하지 않음
- 첫 방문 튜토리얼 팝업: 다음·이전 단계 안내와 자동 표시 끄기 옵션 제공, 메인 화면에서 다시 열기 가능
- 메인 화면에서 최근 게임 검색어 5개를 브라우저에 저장하고 다시 검색
- 아이온2 기본 화면: 게시물 검색·유형 필터와 크롤링 소식 목록
- 게시판 화면: 게시물 검색, 유형 필터, 상세 화면 이동
- 게시물 목록: 제목과 출처·게시일, 읽음 표시를 제공하며 요약은 상세 화면에서 확인
- 상세 화면: 큰 글씨의 전체 내용 요약, 원문 파트별 AI 분석, 게시일, 수정일, 공식 원문 링크
- 공지의 AI 요약·분석·중요 항목에서 쿠폰, 기간, 이벤트, 직업 변경 등 행동 단서를 찾아 패치 후 할 일을 추천하고 완료 상태를 브라우저 `localStorage`에 저장
- 읽음 표시와 소식 북마크를 브라우저 `localStorage`에 저장하고 북마크 페이지에서 모아보기
- 대시보드에서 팔로우 게임과 북마크를 관리하고 개인 글을 작성·열람·삭제
- 팔로우한 게임의 새 크롤링 글 알림과 선택형 브라우저 알림
- 다크·라이트 모드 전환과 브라우저별 테마 저장
- 정보 신고 양식, 모바일 메뉴, 반응형 레이아웃

로컬에서 커뮤니티를 확인하려면 `node server.js`를 실행하고 `http://localhost:4173`에 접속하세요. 이 모드는 계정, 세션, 게시글, 댓글, 반응, 알림, 신고를 `.private/community.json`에 저장합니다. `.private`는 Git에서 제외됩니다. 로컬 JSON 저장소와 Vercel PostgreSQL은 서로 별개이며 자동 동기화되지 않습니다. `file://`로 직접 열면 서버에 저장되는 커뮤니티 기능은 사용할 수 없습니다.

## Vercel에 올려 원격 테스트하기

Vercel 배포는 `api/community.js` 함수와 PostgreSQL 데이터베이스를 사용합니다. 서버리스 함수의 파일 저장소는 요청 사이에 유지되지 않기 때문에 로컬용 `.private/community.json`을 배포 환경의 저장소로 사용하지 않습니다. 로컬 데이터는 자동으로 이전되지 않으며, 배포된 앱에서 만들어진 계정과 글은 연결한 데이터베이스에 저장됩니다.

1. Vercel 프로젝트에서 **Marketplace → Neon**(또는 PostgreSQL 제공자)을 선택해 데이터베이스를 만들고 이 프로젝트에 연결합니다. Vercel은 Marketplace 데이터베이스 제공자와 환경 변수 연결을 지원합니다 ([Vercel 데이터베이스 안내](https://vercel.com/docs/postgres), [Marketplace 저장소 안내](https://vercel.com/docs/marketplace-storage)).
2. 프로젝트 **Settings → Environment Variables**에서 배포 환경(Production, 필요하면 Preview)에 `DATABASE_URL` 또는 `POSTGRES_URL` 연결 문자열이 설정됐는지 확인합니다. 연결 과정에서 변수가 자동으로 추가되지 않았다면 DB 제공자의 pooled connection string을 `DATABASE_URL`로 등록하세요.
3. 선택 사항으로 `TODAYPATCH_ADMIN_TOKEN`에 운영자만 아는 긴 임의 문자열을 등록합니다.
4. 환경 변수를 추가·변경한 뒤에는 **Deployments**에서 새 배포를 만듭니다. Vercel은 환경 변수 변경을 기존 배포에 소급 적용하지 않습니다 ([환경 변수 설정 안내](https://vercel.com/docs/environment-variables)).
5. 배포된 사이트에서 **로그인 → 계정 만들기**를 눌러 이메일, 닉네임, 10자 이상 비밀번호로 가입합니다. 첫 커뮤니티 API 요청 때 계정·세션·게시글 등 테이블과 기존 테이블의 이메일·비밀번호 열이 자동으로 준비됩니다.
6. 가입한 뒤 같은 이메일과 비밀번호로 다른 기기에서도 로그인할 수 있습니다. 기존 게스트 계정으로 로그인되어 있다면 **계정 연결**을 눌러 이메일을 등록하면 그 계정의 게시글과 댓글을 이어서 보존합니다.

비밀번호는 원문으로 저장하지 않고 scrypt 해시로 저장합니다. 이메일 인증, 비밀번호 재설정, 소셜 로그인은 아직 제공하지 않으므로 비밀번호를 안전하게 보관하세요. 계정 가입·로그인과 커뮤니티 콘텐츠는 PostgreSQL에 저장되지만, 팔로우·북마크·읽음 상태·개인 메모 등은 현재 브라우저 `localStorage`에 있어 기기 간 동기화되지 않습니다.

코드를 바꿔 다시 배포할 때는 GitHub에 변경 사항을 push하면 됩니다. 로컬에서 Vercel API와 같은 DB를 사용해 개발하려면 Vercel CLI로 프로젝트를 연결한 뒤 `npx vercel env pull .env.local` 및 `npx vercel dev`를 사용하세요. 일반 `node server.js`는 기존 로컬 JSON 데이터를 사용합니다.

Vercel DB에 저장된 계정은 쿠키를 지워도 이메일과 비밀번호로 다시 로그인할 수 있습니다. 신고 검토 화면은 서버 환경 변수 `TODAYPATCH_ADMIN_TOKEN`과 일치하는 토큰을 입력한 운영자에게만 열립니다. 운영자 토큰은 브라우저 탭 메모리에서만 사용합니다. 신고는 운영자가 직접 검토하며, AI 분류 보조는 아직 연결하지 않았습니다.

크롤링 데이터는 현재 아이온2 공지, 업데이트, CM 아지트 게시판에 한정됩니다. 커뮤니티의 데이터 구조와 화면은 게임 ID를 기준으로 여러 게임에서 공통으로 사용하며, 초기 게시판 필터는 아이온2로 시작합니다. CM 아지트 항목은 아이온2 소식 화면에만 표시됩니다. 패치 후 할 일은 수집된 분석 정보와 날짜·조건 단서에서 규칙 기반으로 추정하며, 추천 근거 게시물로 연결됩니다. 팔로우, 북마크, 읽음 표시, 개인 작성 글은 브라우저별 설정으로 유지됩니다. 커뮤니티 글은 개인 글과 다른 API 및 서버 저장소를 사용합니다. 크롤링 소식 알림은 방문 또는 새로고침 때 확인하며, 백그라운드 푸시는 제공하지 않습니다.
